Function "vault_program_id":
- Returns a hardcoded Pubkey for the vault program
- Uses unwrap which may panic if the string is invalid

Function "action_as_str":
- Converts a u8 action code to a string representation
- Matches 0 to "Create", 1 to "Deposit", 2 to "Withdraw", others to "Unknown"

Function "send_create_vault_transaction":
- Constructs a CPI instruction for vault creation
- Uses invoke_signed with vault seeds for PDA signing
- Includes system program in account metas

Function "send_instr_to_vault_transaction":
- Constructs CPI instructions for deposit/withdraw operations
- Formats instruction data with amount and pubkey
- Uses invoke_signed with vault seeds

Function "process_instruction":
- Main entry point that unpacks and routes instructions
- Handles 8 different instruction types
- Calls appropriate handler functions based on instruction variant

Function "create_admin":
- Creates admin PDA account with system program CPI
- Validates signer and account ownership
- Stores admin ID and timestamp in account data
- Uses bump seed for PDA derivation

Function "update_admin":
- Updates admin account with new admin pubkey
- Validates current admin privileges
- Updates timestamp on change
- Requires signer to be current admin

Function "create_account":
- Creates user PDA account with initial governance points
- Uses user's pubkey in PDA seeds for uniqueness
- Initializes with 10 governance points
- Validates signer and account ownership

Function "open_proposal":
- Creates proposal PDA account with title-based seeds
- Sets proposal duration to 1 hour from creation
- Validates user account ownership
- Stores proposal metadata and voting state

Function "vote_process":
- Records user votes with vote weight based on governance points
- Creates vote record PDA account
- Validates proposal is still active
- Updates yes/no vote counts
- Prevents double voting by checking account initialization

Function "manage_governance_points":
- Admin function to add/subtract governance points from users
- Validates admin privileges
- Uses checked arithmetic to prevent underflow
- Updates user account data

Function "execute_instruction":
- Handles cross-program invocations to vault program
- Validates account types based on instruction variant
- Checks previous instruction for vault program confirmation
- Routes to appropriate vault transaction functions

Function "make_decision":
- Finalizes proposal voting after end time
- Validates admin privileges
- Compares yes/no votes to determine outcome
- Marks proposal as executed
- Prevents execution before proposal end time
