Function "vault_program_id":
- Returns a hardcoded Pubkey for the vault program
- Uses unwrap which may panic if the string is invalid

Function "action_as_str":
- Maps a u8 action code to a string description
- Returns "Unknown" for unrecognized action codes

Function "send_create_vault_transaction":
- Constructs an instruction for creating a vault
- Uses invoke_signed to call an external vault program
- Includes system program in account metas
- Uses vault_bump for PDA derivation

Function "send_instr_to_vault_transaction":
- Constructs instructions for deposit/withdraw operations
- Uses invoke_signed to call external vault program
- Does not include system program in account metas
- Uses vault_bump for PDA derivation

Function "process_instruction":
- Main entry point that unpacks and routes instructions
- Matches against InstructionFormat enum variants
- Calls appropriate handler functions based on instruction type

Function "create_admin":
- Creates an admin PDA account
- Checks for signer and account initialization status
- Uses system_instruction::create_account with invoke_signed
- Stores admin ID and timestamp in account data

Function "update_admin":
- Updates the admin account with a new admin ID
- Verifies account ownership and signer
- Updates timestamp when changing admin
- Does not validate new_admin parameter

Function "create_account":
- Creates a user PDA account
- Initializes with 10 governance points
- Uses user's public key in PDA seeds
- Checks for signer and account initialization

Function "open_proposal":
- Creates a proposal PDA account
- Uses title bytes in PDA seeds
- Sets 1-hour voting period from current time
- Stores proposal metadata and voting state

Function "vote_process":
- Processes user votes on proposals
- Creates vote record PDA account
- Adds user's governance points to vote tally
- Checks voting period has not expired
- Prevents double voting by checking account initialization

Function "manage_governance_points":
- Adds or subtracts governance points from users
- Requires admin signature
- No validation on amount (potential overflow/underflow)
- Directly modifies user account data

Function "execute_instruction":
- Executes vault operations (create/deposit/withdraw)
- Validates account types based on operation
- Checks previous instruction was from vault program
- Calls appropriate vault transaction functions

Function "make_decision":
- Finalizes proposal voting after end time
- Compares yes vs no votes
- Marks proposal as executed
- Requires admin signature to finalize
