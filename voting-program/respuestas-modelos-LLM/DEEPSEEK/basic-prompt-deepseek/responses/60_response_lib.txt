Function "vault_program_id":
- Returns a hardcoded Pubkey for the vault program
- Uses from_str and unwrap which may panic if the string is invalid

Function "action_as_str":
- Converts a u8 action code to a string representation
- Matches 0 to "Create", 1 to "Deposit", 2 to "Withdraw", others to "Unknown"

Function "send_create_vault_transaction":
- Constructs and sends a cross-program invocation to create a vault
- Uses invoke_signed with vault seeds for PDA signing
- Includes system program in accounts
- Extends instruction data with variant, id_pubkey, and vault_bump

Function "send_instr_to_vault_transaction":
- Constructs and sends a cross-program invocation for vault operations
- Uses invoke_signed with vault seeds for PDA signing
- Extends instruction data with variant, amount, and id_pubkey
- Does not include system program in accounts

Function "process_instruction":
- Main entry point that unpacks instruction data
- Routes to appropriate handler function based on InstructionFormat variant
- Handles CreateAdmin, UpdateAdmin, CreateAccount, OpenProposal, Vote, ManagePoints, ExecuteIntrs, and MakeDecision instructions

Function "create_admin":
- Creates an admin account PDA with "admin" seeds
- Checks for signer and account initialization status
- Stores admin_id and current timestamp
- Uses invoke_signed to create account with system program
- Serializes Admin_Account data

Function "update_admin":
- Updates the admin account with a new admin ID
- Verifies current admin privileges and PDA address
- Updates timestamp and serializes new admin data
- Requires signer and program ownership validation

Function "create_account":
- Creates a user account PDA with "userAccount" seeds including user pubkey
- Initializes with 10 governance points
- Uses invoke_signed to create account with system program
- Checks for signer and account initialization status

Function "open_proposal":
- Creates a proposal account PDA with "proposal" seeds including title
- Sets start time to current time and end time to 1 hour later
- Initializes vote counts to zero and executed to false
- Uses invoke_signed to create account with system program

Function "vote_process":
- Records a vote on a proposal
- Creates vote record account PDA with "vote" seeds including user and proposal
- Adds user's governance points to yes/no votes based on vote_answer
- Checks proposal is still active (within end_time)
- Uses invoke_signed to create vote record account

Function "manage_governance_points":
- Adds or subtracts governance points from a user account
- Requires admin privileges to execute
- Validates admin PDA and signer status
- Updates user's governance points based on instruction boolean

Function "execute_instruction":
- Executes cross-program invocations to vault program
- Validates user account type based on variant_instr (0=admin, 1=user, 2=admin)
- Checks previous instruction was from vault program using instruction sysvar
- Routes to appropriate send function based on variant_instr

Function "make_decision":
- Finalizes a proposal after end_time has passed
- Requires admin privileges to execute
- Compares yes_votes vs no_votes and marks proposal as executed
- Checks proposal has ended before making decision
