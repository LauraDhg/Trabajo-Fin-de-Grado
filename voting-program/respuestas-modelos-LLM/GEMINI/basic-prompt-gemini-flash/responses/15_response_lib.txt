Function "vault_program_id":
- Returns a hardcoded Pubkey.

Function "process_instruction":
- Unpacks the instruction data using `InstructionFormat::unpack`.
- Matches the unpacked instruction to call the corresponding function.
- Acts as the main dispatcher for the program's instructions.

Function "create_admin":
- Creates an admin account.
- Checks if the admin payer is a signer.
- Checks if the admin account has already been initialized.
- Derives the admin account's PDA.
- Creates the admin account using `invoke_signed` and `system_instruction::create_account`.
- Serializes the admin account data.

Function "update_admin":
- Updates the admin account with a new admin Pubkey.
- Checks if the admin payer is a signer.
- Checks if the admin account is owned by the program.
- Derives the admin account's PDA.
- Deserializes the admin account data.
- Checks if the current admin is the signer.
- Updates the admin ID and last update timestamp.
- Serializes the updated admin account data.

Function "create_account":
- Creates a user account.
- Checks if the user payer is a signer.
- Checks if the user account has already been initialized.
- Derives the user account's PDA using `user_payer.key`.
- Creates the user account using `invoke_signed` and `system_instruction::create_account`.
- Serializes the user account data.

Function "open_proposal":
- Opens a new proposal.
- Checks if the user payer is a signer.
- Checks if the proposal account has already been initialized.
- Derives the proposal account's PDA using the proposal title.
- Deserializes the user account data.
- Checks if the account type is valid.
- Creates the proposal account using `invoke_signed` and `system_instruction::create_account`.
- Serializes the proposal data.

Function "vote_process":
- Processes a vote on a proposal.
- Checks if the user payer is a signer.
- Checks if the proposal and user accounts are owned by the program.
- Checks if the vote record account has already been initialized.
- Derives the vote record account's PDA.
- Deserializes the proposal and user account data.
- Checks if the account type is valid.
- Checks if the proposal is still open.
- Updates the proposal's vote counts based on the vote answer.
- Creates the vote record account.
- Serializes the vote record and proposal data.

Function "manage_governance_points":
- Adds or subtracts governance points from a user account.
- Checks if the admin payer is a signer.
- Checks if the admin and user accounts are owned by the program.
- Derives the admin account's PDA.
- Deserializes the admin and user account data.
- Checks if the current admin is the signer.
- Adds or subtracts the specified amount from the user's governance points.
- Serializes the updated user account data.

Function "execute_instruction":
- Executes a vault-related instruction via CPI (Cross-Program Invocation).
- Checks if the user payer is a signer.
- Checks if the user account is owned by the program.
- Checks that the user account is initialized (has lamports).
- Performs different checks based on the `variant_instr`.
- Loads the current instruction index and checks the previous instruction.
- Calls `send_create_vault_transaction` or `send_instr_to_vault_transaction` based on the `variant_instr`.

Function "make_decision":
- Finalizes a proposal by determining if it passes or fails.
- Checks if the admin payer is a signer.
- Checks if the admin and proposal accounts are owned by the program.
- Derives the admin account's PDA.
- Deserializes the admin and proposal account data.
- Checks if the current admin is the signer.
- Checks if the proposal's voting period has ended.
- Determines if the proposal passes based on the yes and no vote counts.
- Sets the proposal's `executed` flag to `true`.
- Serializes the updated proposal data.
