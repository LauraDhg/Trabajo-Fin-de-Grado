Function "vault_program_id":
- Returns a hardcoded Pubkey, which represents the ID of the vault program.

Function "process_instruction":
- Unpacks the instruction data into an `InstructionFormat` enum.
- Matches the instruction and calls the corresponding function.

Function "create_admin":
- Creates an admin account.
- Checks if the admin payer is a signer.
- Checks if the admin account has already been initialized.
- Derives the admin account's PDA.
- Checks if the clock sysvar is valid.
- Creates an `Admin_Account` struct.
- Calculates the rent required for the account.
- Creates the admin account using `invoke_signed`.
- Serializes the admin account data.

Function "update_admin":
- Updates the admin account.
- Checks if the admin account's owner is the program.
- Checks if the admin payer is a signer.
- Deserializes the admin account data.
- Derives the admin account's PDA.
- Checks if the clock sysvar is valid.
- Updates the admin ID and last update timestamp.
- Serializes the updated admin account data.

Function "create_account":
- Creates a user account.
- Checks if the user payer is a signer.
- Checks if the user account has already been initialized.
- Derives the user account's PDA.
- Creates a `User_Account` struct.
- Calculates the rent required for the account.
- Creates the user account using `invoke_signed`.
- Serializes the user account data.

Function "open_proposal":
- Creates a proposal account.
- Checks if the user account's owner is the program.
- Checks if the user payer is a signer.
- Checks if the proposal account has already been initialized.
- Derives the proposal account's PDA.
- Deserializes the user account data.
- Checks if the account is a valid User account.
- Checks if the clock sysvar is valid.
- Calculates the start and end times for the proposal.
- Creates a `Proposal` struct.
- Calculates the rent required for the account.
- Creates the proposal account using `invoke_signed`.
- Serializes the proposal account data.

Function "vote_process":
- Processes a vote for a proposal.
- Checks if the user account and proposal account owners are the program.
- Checks if the user payer is a signer.
- Checks if the vote record account has already been initialized.
- Derives the vote record account's PDA.
- Deserializes the proposal and user account data.
- Checks if the user account is a valid User account.
- Creates a `Vote_Record` struct.
- Checks if the clock sysvar is valid.
- Checks if the proposal is still open.
- Updates the proposal's yes or no votes based on the user's vote and governance points.
- Calculates the rent required for the vote record account.
- Creates the vote record account using `invoke_signed`.
- Serializes the vote record, proposal, and user account data.

Function "manage_governance_points":
- Manages the governance points of a user account.
- Checks if the admin and user account owners are the program.
- Checks if the admin payer is a signer.
- Derives the admin account's PDA.
- Deserializes the user account data.
- Checks if the user account is a valid User account.
- Adds or subtracts governance points from the user account.
- Serializes the updated user account data.

Function "execute_instruction":
- Executes an instruction related to a vault program.
- Checks if the user account's owner is the program.
- Checks if the user payer is a signer.
- Checks if the user account is initialized.
- Performs different actions based on the `variant_instr` value (0: CREAR VAULT, 1: DEPOSITAR, 2: WITHDRAW).  The logic within the match statement is incomplete and only checks if the `user_account_dao` matches either admin or user PDA. It does not actually perform the vault creation, deposit, or withdraw operations.
- Checks if the vault program ID and instructions sysvar ID are correct.
- Loads the current instruction index and checks if the previous instruction was related to the vault program.
- Calls `send_create_vault_transaction` or `send_instr_to_vault_transaction` based on the `variant_instr` value.

Function "make_decision":
- Makes a decision on a proposal based on the votes.
- Checks if the admin and proposal account owners are the program.
- Checks if the admin payer is a signer.
- Derives the admin account's PDA.
- Deserializes the proposal data.
- Checks if the clock sysvar is valid.
- Checks if the proposal is still active.
- Compares the yes and no votes and logs whether the proposal was approved or denied.
- Sets the `executed` flag on the proposal to true.
- Serializes the updated proposal data.
