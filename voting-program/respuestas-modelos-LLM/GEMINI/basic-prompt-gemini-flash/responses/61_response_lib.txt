Function "vault_program_id":
- Returns a Pubkey.
- Returns the Pubkey of the Vault program.
- Pubkey is hardcoded.

Function "action_as_str":
- Takes a u8 representing an action as input.
- Returns a string slice representing the action.
- Matches the input u8 to a string slice.
- Returns "Unknown" if the input is not a valid action.

Function "send_create_vault_transaction":
- Takes several account info structs and parameters for creating a vault.
- Creates an instruction to call the vault program to create a vault.
- Signs the instruction with the vault's seed.
- Invokes the vault program with the created instruction.

Function "send_instr_to_vault_transaction":
- Takes several account info structs and parameters for sending instructions to the vault.
- Creates an instruction to call the vault program.
- Signs the instruction with the vault's seed.
- Invokes the vault program with the created instruction.

Function "process_instruction":
- Entrypoint of the program.
- Unpacks the instruction data into an `InstructionFormat` enum.
- Matches on the `InstructionFormat` and calls the corresponding function.

Function "create_admin":
- Creates an admin account.
- Takes the program ID, accounts, and admin bump seed as input.
- Checks if the admin payer is a signer.
- Checks if the admin account has already been initialized.
- Derives the admin account PDA.
- Validates the admin account PDA.
- Validates the clock sysvar.
- Creates an `Admin_Account` struct.
- Serializes the admin account data.

Function "update_admin":
- Updates the admin account.
- Takes the program ID, accounts, new admin Pubkey, and admin bump seed as input.
- Checks if the admin account owner is the program ID.
- Checks if the admin payer is a signer.
- Unpacks the admin account data.
- Derives the admin account PDA.
- Validates the admin account PDA.
- Validates the clock sysvar.
- Updates the admin ID in the `Admin_Account` struct.
- Serializes the updated admin account data.

Function "create_account":
- Creates a user account.
- Takes the program ID, accounts, and user bump seed as input.
- Checks if the user payer is a signer.
- Checks if the user account has already been initialized.
- Derives the user account PDA.
- Validates the user account PDA.
- Creates a `User_Account` struct.
- Serializes the user account data.

Function "open_proposal":
- Opens a new proposal.
- Takes the program ID, accounts, title, description, and proposal bump seed as input.
- Checks if the user account owner is the program ID.
- Checks if the user payer is a signer.
- Checks if the proposal account has already been initialized.
- Derives the proposal account PDA.
- Validates the proposal account PDA.
- Validates the clock sysvar.
- Creates a `Proposal` struct.
- Serializes the proposal account data.

Function "vote_process":
- Processes a vote on a proposal.
- Takes the program ID, accounts, vote answer, and vote bump seed as input.
- Checks if the user and proposal account owners are the program ID.
- Checks if the user payer is a signer.
- Checks if the vote record account has already been initialized.
- Derives the vote record account PDA.
- Validates the vote record account PDA.
- Unpacks the proposal and user account data.
- Creates a `Vote_Record` struct.
- Validates the clock sysvar.
- Checks if the proposal is still open.
- Updates the yes or no votes on the proposal based on the vote answer.
- Serializes the vote record, proposal, and user account data.

Function "manage_governance_points":
- Manages the governance points of a user account.
- Takes the program ID, accounts, amount, admin bump seed, and instruction (add/subtract) as input.
- Checks if the admin and user account owners are the program ID.
- Checks if the admin payer is a signer.
- Derives the admin account PDA.
- Validates the admin account PDA.
- Unpacks the user account data.
- Adds or subtracts the amount from the user's governance points.
- Serializes the updated user account data.

Function "execute_instruction":
- Executes an instruction based on the `variant_instr`.
- Takes the program ID, accounts, variant instruction, amount, vault bump seed, and user bump seed as input.
- Checks if the user account owner is the program ID.
- Checks if the user payer is a signer.
- Checks if the user account has been initialized.
- Performs different checks based on the `variant_instr`.
- Validates the vault program ID and instruction sysvar ID.
- Loads the current instruction index and previous instruction.
- Calls the `send_create_vault_transaction` or `send_instr_to_vault_transaction` function based on the `variant_instr`.

Function "make_decision":
- Makes a decision on a proposal based on the votes.
- Takes the program ID, accounts, and admin bump seed as input.
- Checks if the admin and proposal account owners are the program ID.
- Checks if the admin payer is a signer.
- Derives the admin account PDA.
- Validates the admin account PDA.
- Unpacks the proposal data.
- Validates the clock sysvar.
- Checks if the proposal is still active.
- Determines if the proposal is approved or denied based on the yes and no votes.
- Updates the executed flag on the proposal.
- Serializes the updated proposal data.
