Function "vault_program_id":
- Returns a hardcoded `Pubkey`.

Function "action_as_str":
- Takes a `u8` representing an action.
- Returns a string slice (`&'static str`) describing the action.
- Handles actions 0, 1, and 2, and returns "Unknown" for any other value.

Function "send_create_vault_transaction":
- Sends a cross-program invocation (CPI) to the vault program to create a vault.
- Takes the variant instruction, ID pubkey, vault bump seed, admin payer, admin account, vault account, vault program, and system program as input.
- Constructs the instruction data and accounts for the CPI.
- Uses `invoke_signed` to send the transaction, including the vault PDA's seeds for signing.

Function "send_instr_to_vault_transaction":
- Sends a cross-program invocation (CPI) to the vault program to perform an action on the vault.
- Takes the variant instruction, ID pubkey, amount, vault bump seed, user payer, user account, and vault account as input.
- Constructs the instruction data and accounts for the CPI.
- Uses `invoke_signed` to send the transaction, including the vault PDA's seeds for signing.

Function "process_instruction":
- Entrypoint of the program.
- Unpacks the instruction data into an `InstructionFormat` enum.
- Matches on the `InstructionFormat` enum and calls the appropriate handler function.

Function "create_admin":
- Creates an admin account.
- Takes the program ID, accounts, and admin bump seed as input.
- Checks that the admin payer is a signer.
- Checks if the admin account has already been initialized.
- Derives the admin PDA.
- Checks that the admin account key matches the derived PDA.
- Creates the admin account using `invoke_signed`.
- Serializes the `Admin_Account` struct into the admin account's data.

Function "update_admin":
- Updates the admin account with a new admin.
- Takes the program ID, accounts, new admin `Pubkey`, and admin bump seed as input.
- Checks that the admin account's owner is the program ID.
- Checks that the admin payer is a signer.
- Deserializes the admin account data into an `Admin_Account` struct.
- Derives the admin PDA.
- Checks that the admin account key matches the derived PDA.
- Updates the admin ID and last update timestamp.
- Serializes the updated `Admin_Account` struct back into the admin account's data.

Function "create_account":
- Creates a user account.
- Takes the program ID, accounts, and user bump seed as input.
- Checks that the user payer is a signer.
- Checks if the user account has already been initialized.
- Derives the user PDA.
- Checks that the user account key matches the derived PDA.
- Creates the user account using `invoke_signed`.
- Serializes the `User_Account` struct into the user account's data.

Function "open_proposal":
- Creates a new proposal account.
- Takes the program ID, accounts, title, description, and proposal bump seed as input.
- Checks that the user account's owner is the program ID.
- Checks that the user payer is a signer.
- Checks if the proposal account has already been initialized.
- Derives the proposal PDA.
- Checks that the proposal account key matches the derived PDA.
- Creates the proposal account using `invoke_signed`.
- Serializes the `Proposal` struct into the proposal account's data.

Function "vote_process":
- Processes a user's vote on a proposal.
- Takes the program ID, accounts, vote answer (boolean), and vote bump seed as input.
- Checks that the user account's and proposal account's owner is the program ID.
- Checks that the user payer is a signer.
- Checks if the vote record account has already been initialized.
- Derives the vote PDA.
- Checks that the vote record account key matches the derived PDA.
- Deserializes the proposal and user account data.
- Checks if the voting period is still open.
- Updates the yes/no votes on the proposal based on the user's vote.
- Creates the vote record account using `invoke_signed`.
- Serializes the vote record, proposal, and user account data.

Function "manage_governance_points":
- Adds or subtracts governance points from a user's account.
- Takes the program ID, accounts, amount, admin bump seed, and instruction (add/subtract) as input.
- Checks that the admin account's and user account's owner is the program ID.
- Checks that the admin payer is a signer.
- Derives the admin PDA.
- Checks that the admin account key matches the derived PDA.
- Deserializes the user account data.
- Adds or subtracts the specified amount from the user's governance points.
- Serializes the updated user account data.

Function "execute_instruction":
- Executes an instruction related to a vault program.
- Takes the program ID, accounts, variant instruction, amount, vault bump seed, and user bump seed as input.
- Checks that the user account's owner is the program ID.
- Checks that the user payer is a signer.
- Checks if the user account has lamports.
- Uses a `match` statement to perform different actions based on the `variant_instr`.
- Loads the current and previous instructions to check for vault program confirmation.
- Calls either `send_create_vault_transaction` or `send_instr_to_vault_transaction` based on the `variant_instr`.

Function "make_decision":
- Makes a decision on a proposal based on the vote outcome.
- Takes the program ID, accounts, and admin bump seed as input.
- Checks that the admin account's and proposal account's owner is the program ID.
- Checks that the admin payer is a signer.
- Derives the admin PDA.
- Checks that the admin account key matches the derived PDA.
- Deserializes the proposal data.
- Checks if the voting period has ended.
- Determines if the proposal is approved or denied based on the vote count.
- Sets the `executed` flag on the proposal.
- Serializes the updated proposal data.
