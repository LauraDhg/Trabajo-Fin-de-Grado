Function "vault_program_id":
- Returns a Pubkey.
- The Pubkey is hardcoded as "6dVLkpmd5BvVQF7oXpipnQFtKwba2uQkMMwzHnaqf8Gr".

Function "action_as_str":
- Takes a u8 representing an action.
- Returns a string slice (&'static str) describing the action.
- Matches the input u8 to action types (0: "Create", 1: "Deposit", 2: "Withdraw").
- Returns "Unknown" if the input doesn't match any defined action.

Function "send_create_vault_transaction":
- Sends a CPI (Cross-Program Invocation) to the vault program to create a vault.
- Takes various account infos, the variant instruction, the id pubkey and vault bump seed.
- Constructs an instruction with the provided data.
- Invokes the vault program using `invoke_signed` with the provided accounts and seeds.

Function "send_instr_to_vault_transaction":
- Sends a CPI to the vault program to deposit or withdraw.
- Takes various account infos, the variant instruction, the id pubkey, the amount and vault bump seed.
- Constructs an instruction with the provided data.
- Invokes the vault program using `invoke_signed` with the provided accounts and seeds.

Function "process_instruction":
- Entry point of the Solana program.
- Deserializes the instruction data using `InstructionFormat::unpack`.
- Matches the unpacked instruction to call the corresponding function.
- Dispatches instructions to functions like `create_admin`, `update_admin`, `create_account`, `open_proposal`, `vote_process`, `manage_governance_points`, `execute_instruction` and `make_decision`.

Function "create_admin":
- Creates an admin account.
- Checks if the admin payer is a signer.
- Checks if the admin account has already been initialized.
- Derives the admin account PDA (Program Derived Address).
- Checks if the provided admin account matches the derived PDA.
- Gets the clock sysvar and retrieves the current timestamp.
- Creates an `Admin_Account` struct.
- Calculates rent exemption and creates the admin account using `invoke_signed`.
- Serializes the admin account data.

Function "update_admin":
- Updates the admin account.
- Checks if the admin account's owner is the program.
- Checks if the admin payer is a signer.
- Deserializes the admin account data.
- Derives the admin account PDA.
- Checks if the provided admin account matches the derived PDA.
- Gets the clock sysvar and retrieves the current timestamp.
- Updates the admin ID and last update timestamp.
- Serializes the updated admin account data.

Function "create_account":
- Creates a user account.
- Checks if the user payer is a signer.
- Checks if the user account has already been initialized.
- Derives the user account PDA.
- Checks if the provided user account matches the derived PDA.
- Creates a `User_Account` struct, initializing governance points to 10.
- Calculates rent exemption and creates the user account using `invoke_signed`.
- Serializes the user account data.

Function "open_proposal":
- Opens a new proposal.
- Checks if the user account's owner is the program.
- Checks if the user payer is a signer.
- Checks if the proposal account has already been initialized.
- Derives the proposal account PDA.
- Checks if the provided proposal account matches the derived PDA.
- Gets the clock sysvar and retrieves the current timestamp.
- Sets the proposal start and end times (end time is 1 hour after start).
- Creates a `Proposal` struct.
- Calculates rent exemption and creates the proposal account using `invoke_signed`.
- Serializes the proposal account data.

Function "vote_process":
- Processes a vote for a proposal.
- Checks if the user and proposal account's owner is the program.
- Checks if the user payer is a signer.
- Checks if the vote record account has already been initialized.
- Derives the vote record account PDA.
- Checks if the provided vote record account matches the derived PDA.
- Deserializes the proposal and user account data.
- Creates a `Vote_Record` struct.
- Gets the clock sysvar and retrieves the current timestamp.
- Checks if the voting period is still open.
- Updates the yes/no votes count based on the user's vote and governance points.
- Calculates rent exemption and creates the vote record account using `invoke_signed`.
- Serializes the vote record, proposal and user account data.

Function "manage_governance_points":
- Manages (adds or subtracts) governance points for a user.
- Checks if the admin and user account's owner is the program.
- Checks if the admin payer is a signer.
- Derives the admin account PDA.
- Checks if the provided admin account matches the derived PDA.
- Deserializes the user account data.
- Adds or subtracts the specified amount of governance points.
- Serializes the updated user account data.

Function "execute_instruction":
- Executes an instruction based on the provided variant.
- Checks if the user account's owner is the program.
- Checks if the user payer is a signer.
- Checks if the user account has been initialized.
- Checks the variant instruction and calls others functions to validate the action.
- Validates the vault program ID and instruction sysvar ID.
- Loads the current instruction index.
- Checks if the previous instruction was a vault program confirmation.
- Calls `send_create_vault_transaction` or `send_instr_to_vault_transaction` based on the variant.

Function "make_decision":
- Makes a decision on a proposal based on the votes.
- Checks if the admin and proposal account's owner is the program.
- Checks if the admin payer is a signer.
- Derives the admin account PDA.
- Checks if the provided admin account matches the derived PDA.
- Deserializes the proposal account data.
- Gets the clock sysvar and retrieves the current timestamp.
- Checks if the proposal is still active.
- Determines if the proposal is approved based on yes/no votes.
- Sets the proposal's executed status.
- Serializes the updated proposal account data.
