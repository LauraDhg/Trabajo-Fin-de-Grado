Function "vault_program_id":
- Returns a hardcoded `Pubkey`.

Function "process_instruction":
- Unpacks the instruction data using `InstructionFormat::unpack`.
- Matches the unpacked instruction to the corresponding handler function.
- Dispatches to different functions based on the unpacked `InstructionFormat` enum.

Function "create_admin":
- Creates an admin account.
- Takes `admin_bump` as an argument for PDA derivation.
- Checks if the `admin_payer` is a signer.
- Checks if the `admin_account_dao` account has already been initialized (lamports > 0).
- Derives the admin PDA using `Pubkey::create_program_address`.
- Checks if the derived PDA matches the `admin_account_dao` account's `Pubkey`.
- Creates the admin account using `invoke_signed` and `system_instruction::create_account`.
- Serializes the `Admin_Account` data into the newly created account.

Function "update_admin":
- Updates the admin account with a new admin `Pubkey`.
- Takes `new_admin` and `admin_bump` as arguments.
- Checks if the `admin_account_dao` account is owned by the program.
- Checks if the `admin_payer` is a signer.
- Deserializes the `Admin_Account` data.
- Derives the admin PDA and checks if it matches the `admin_account_dao` account's `Pubkey`.
- Updates the `admin_id` field of the `Admin_Account` with the `new_admin` `Pubkey`.
- Serializes the updated `Admin_Account` data back into the account.

Function "create_account":
- Creates a user account.
- Takes `user_bump` as an argument for PDA derivation.
- Checks if the `user_payer` is a signer.
- Checks if the `user_account_dao` account has already been initialized.
- Derives the user PDA using `Pubkey::create_program_address`.
- Checks if the derived PDA matches the `user_account_dao` account's `Pubkey`.
- Creates the user account using `invoke_signed` and `system_instruction::create_account`.
- Serializes the `User_Account` data into the newly created account.

Function "open_proposal":
- Creates a proposal account.
- Takes `title`, `description`, and `proposal_bump` as arguments.
- Checks if the `user_account_dao` account is owned by the program.
- Checks if the `user_payer` is a signer.
- Checks if the `proposal_account` account has already been initialized.
- Derives the proposal PDA using `Pubkey::create_program_address`.
- Checks if the derived PDA matches the `proposal_account` account's `Pubkey`.
- Deserializes the `User_Account` data.
- Sets the `start_time` and `end_time` for the proposal.
- Creates the proposal account using `invoke_signed` and `system_instruction::create_account`.
- Serializes the `Proposal` data into the newly created account.

Function "vote_process":
- Processes a user's vote on a proposal.
- Takes `vote_answer` (boolean) and `vote_bump` as arguments.
- Checks if the `user_account_dao` and `proposal_account` accounts are owned by the program.
- Checks if the `user_payer` is a signer.
- Checks if the `vote_record_account` has already been initialized.
- Derives the vote PDA using `Pubkey::create_program_address`.
- Checks if the derived PDA matches the `vote_record_account` account's `Pubkey`.
- Deserializes the `Proposal` and `User_Account` data.
- Checks if the proposal is still open (current time is before `end_time`).
- Updates the `yes_votes` or `no_votes` count of the proposal based on `vote_answer`.
- Creates the vote record account using `invoke_signed` and `system_instruction::create_account`.
- Serializes the `Vote_Record` data into the newly created account.
- Serializes the updated `Proposal` and `User_Account` data back into their accounts.

Function "manage_governance_points":
- Adds or subtracts governance points from a user's account.
- Takes `amount`, `admin_bump`, and `instruction` (boolean: add or subtract) as arguments.
- Checks if the `admin_account_dao` and `user_account_dao` accounts are owned by the program.
- Checks if the `admin_payer` is a signer.
- Derives the admin PDA and checks if it matches the `admin_account_dao` account's `Pubkey`.
- Deserializes the `User_Account` data.
- Adds or subtracts the specified `amount` from the user's `amount_governance_points` field.
- Serializes the updated `User_Account` data back into the account.

Function "execute_instruction":
- Executes a vault instruction (create, deposit, or withdraw).
- Takes `variant_instr`, `amount`, `vault_bump`, and `user_bump` as arguments.
- Checks if the `user_account_dao` account is owned by the program.
- Checks if the `user_payer` is a signer.
- Checks if the `user_account_dao` account has lamports.
- Checks if the keys used for PDA creation are equals to the account passed.
- Checks if the previous instruction confirms the vault program.
- Calls either `send_create_vault_transaction` or `send_instr_to_vault_transaction` based on the `variant_instr`.

Function "make_decision":
- Finalizes a proposal based on the votes.
- Takes `admin_bump` as an argument.
- Checks if the `admin_account_dao` and `proposal_account` accounts are owned by the program.
- Checks if the `admin_payer` is a signer.
- Derives the admin PDA and checks if it matches the `admin_account_dao` account's `Pubkey`.
- Deserializes the `Proposal` data.
- Checks if the proposal's voting period is over (current time is after `end_time`).
- Sets the `executed` field of the proposal to `true`.
- Serializes the updated `Proposal` data back into the account.

Function "send_create_vault_transaction":
- Creates a cross-program invocation (CPI) to the vault program to create a new vault.
- Takes `variant_instr`, `id_pubkey`, `vault_bump`, and several account `AccountInfo` references as arguments.
- Creates the instruction data by concatenating the `variant_instr`, `id_pubkey`, and `vault_bump`.
- Creates the `Instruction` with the vault program's ID, accounts, and data.
- Invokes the vault program using `invoke_signed` with the appropriate accounts and seeds.

Function "send_instr_to_vault_transaction":
- Creates a cross-program invocation (CPI) to the vault program to deposit to, or withdraw from a vault.
- Takes `variant_instr`, `id_pubkey`, `amount`, `vault_bump`, and several account `AccountInfo` references as arguments.
- Creates the instruction data by concatenating the `variant_instr`, `amount`, and `id_pubkey`.
- Creates the `Instruction` with the vault program's ID, accounts, and data.
- Invokes the vault program using `invoke_signed` with the appropriate accounts and seeds.
