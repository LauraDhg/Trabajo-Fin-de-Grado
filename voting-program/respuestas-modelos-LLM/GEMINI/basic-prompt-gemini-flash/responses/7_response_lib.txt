Function "vault_program_id":
- Returns a hardcoded Pubkey for the vault program.
- Using a hardcoded Pubkey is a risk.

Function "send_create_vault_transaction":
- Sends a CPI (Cross-Program Invocation) to create a vault.
- Includes the "vault" seed in the signing seeds.
- The first byte of ix_data determines the variant instruction for the vault program.

Function "send_instr_to_vault_transaction":
- Sends a CPI to the vault program for deposit or withdraw instructions.
- Includes the "vault" seed in the signing seeds.
- The first byte of ix_data determines the variant instruction for the vault program.

Function "process_instruction":
- Entry point of the program.
- Deserializes the instruction data using `InstructionFormat::unpack`.
- Matches the instruction and calls the corresponding function.

Function "create_admin":
- Creates an admin account.
- Checks if the admin payer is a signer.
- Checks if the admin account is already initialized.
- Derives the admin PDA (Program Derived Address) using `Pubkey::find_program_address`.
- Creates the admin account using `system_instruction::create_account` and signs with the admin PDA.
- Serializes the admin account data.

Function "update_admin":
- Updates the admin account with a new admin.
- Checks if the admin account owner is the program.
- Checks if the admin payer is a signer.
- Deserializes the admin account data.
- Derives the admin PDA.
- Checks if the current admin matches the payer.
- Updates the admin_id and last_update fields.
- Serializes the updated admin account data.

Function "create_account":
- Creates a user account.
- Checks if the user payer is a signer.
- Checks if the account is already initialized.
- Derives the user PDA using `Pubkey::find_program_address`.
- Creates the user account using `system_instruction::create_account` and signs with the user PDA.
- Serializes the user account data.
- Assigns initial governance points.

Function "open_proposal":
- Creates a proposal account.
- Checks if the user account owner is the program.
- Checks if the user payer is a signer.
- Checks if the proposal account is already initialized.
- Derives the proposal PDA.
- Deserializes the user account.
- Sets the proposal start and end times.
- Creates the proposal account using `system_instruction::create_account` and signs with the proposal PDA.
- Serializes the proposal data.

Function "vote_process":
- Processes a vote for a proposal.
- Checks if the user and proposal account owners are the program.
- Checks if the user payer is a signer.
- Checks if the vote record account is already initialized.
- Derives the vote PDA.
- Deserializes the proposal and user accounts.
- Checks if the proposal is still open.
- Updates the yes_votes or no_votes count based on the vote answer.
- Creates the vote record account using `system_instruction::create_account` and signs with the vote PDA.
- Serializes the vote record and proposal data.
- Serializes the user data.

Function "manage_governance_points":
- Adds or subtracts governance points from a user account.
- Checks if the admin and user account owners are the program.
- Checks if the admin payer is a signer.
- Derives the admin PDA.
- Deserializes the admin and user accounts.
- Checks if the admin has privileges.
- Adds or subtracts the specified amount from the user's governance points.
- Serializes the user data.
- Uses checked_sub to prevent underflow.

Function "execute_instruction":
- Executes an instruction by sending a CPI to the vault program.
- Checks if the user account owner is the program.
- Checks if the user is a signer.
- Validates user account balance.
- Performs different checks based on the `variant_instr`.
- Checks the previous instruction using `load_instruction_at` to determine if it was a vault program confirmation.
- Calls either `send_create_vault_transaction` or `send_instr_to_vault_transaction` based on the instruction variant.

Function "make_decision":
- Makes a decision on a proposal based on the votes.
- Checks if the admin and proposal account owners are the program.
- Checks if the admin payer is a signer.
- Derives the admin PDA.
- Deserializes the admin and proposal accounts.
- Checks if the admin has privileges.
- Checks if the proposal is still active.
- Sets the executed flag based on whether yes_votes are greater than or equal to no_votes.
- Serializes the proposal data.
