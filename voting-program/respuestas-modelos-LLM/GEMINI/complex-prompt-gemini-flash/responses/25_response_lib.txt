Function "vote_process":
- It processes a user's vote on a proposal.
- The vote record account is created using a PDA derived from the "vote" seed, the user's Pubkey, and the proposal's Pubkey. Ensure that the seed is unique and cannot be easily predicted or manipulated.
- It checks if the vote record account has already been initialized.
- It retrieves the proposal and user account data, and updates the vote counts based on the `vote_answer`.
- It checks if the proposal is still open for voting based on the `start_time` and `end_time` fields.
- It uses `checked_add` to prevent arithmetic overflows when updating the vote counts.
- It uses `invoke_signed` to create the vote record account. Ensure that the seeds and bump are correct.

- It uses `checked_add` to prevent arithmetic overflows when adding governance points.
- It directly subtracts `amount` from `user.amount_governance_points` with the `-` operator, which can cause underflow if amount is bigger. This could be avoided using the `checked_sub` method to prevent this underflow.
