Function "open_proposal":

- The proposal end time is hardcoded to be 1 hour after the start time. This should be configurable.

Function "vote_process":
- The PDA derivation for vote record accounts uses `b"vote"`, the user account's key, and the proposal account's key. This is a good practice.

- The vote amount is directly taken from the user's `amount_governance_points`. Consider implementing a mechanism to limit the voting power or prevent users from voting multiple times.
- The function directly updates the proposal and user accounts after a vote. This could be susceptible to race conditions if multiple users vote simultaneously.
