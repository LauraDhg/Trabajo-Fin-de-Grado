Function "vault_program_id":
- Hardcoded program ID.

Function "process_instruction":
- Central dispatcher for instructions, good practice.

Function "create_admin":
- Creates an admin account.
- Checks if the admin payer is a signer.
- Checks if the admin account is already initialized.
- Derives the admin PDA.
- Creates the admin account using `invoke_signed`.
- Serializes the admin account data.

Function "update_admin":
- Updates the admin account with a new admin.
- Checks if the admin account owner is the program.
- Checks if the admin payer is a signer.
- Deserializes the admin account data.
- Derives the admin PDA.
- Checks if the current admin has admin privileges.
- Updates the admin ID and last update timestamp.
- Serializes the updated admin account data.

Function "create_account":
- Creates a user account.
- Checks if the user payer is a signer.
- Checks if the user account is already initialized.
- Derives the user PDA.
- Creates the user account using `invoke_signed`.
- Serializes the user account data, initializes with 10 governance points.

Function "open_proposal":
- Opens a new proposal.
- Checks if the user account owner is the program.
- Checks if the user payer is a signer.
- Checks if the proposal account is already initialized.
- Derives the proposal PDA using the title.
- Creates the proposal account using `invoke_signed`.
- Serializes the proposal data, sets the end time to 1 hour after the start time.

Function "vote_process":
- Processes a user's vote on a proposal.
- Checks if the user and proposal accounts' owners are the program.
- Checks if the user payer is a signer.
- Checks if the vote record account is already initialized.
- Derives the vote PDA.
- Deserializes the proposal and user account data.
- Creates a vote record.
- Checks if the proposal is still open based on the current time.
- Updates the yes or no votes based on the user's vote.
- Creates the vote record account using `invoke_signed`.
- Serializes the vote record, proposal and user account data.

Function "manage_governance_points":
- Manages user governance points.
- Checks if the admin and user accounts' owners are the program.
- Checks if the admin payer is a signer.
- Derives the admin PDA.
- Deserializes the admin account data.
- Checks if the current admin has admin privileges.
- Deserializes the user account data.
- Adds or subtracts governance points from the user account.
- Serializes the user account data.

Function "execute_instruction":
- Executes instructions related to a vault program.
- Checks if the user account's owner is the program.
- Checks if the user payer is a signer.
- Different branches depending on the instruction.
- Instruction 0, 2 check for admin.
- Instruction 1 checks for user account.
- Checks if the vault program ID and instruction sysvar ID are correct.
- Loads current index.
- Check of previous instruction.
- Executes vault instructions using CPI.

Function "make_decision":
- Makes a decision on a proposal based on the votes.
- Checks if the admin and proposal accounts' owners are the program.
- Checks if the admin payer is a signer.
- Derives the admin PDA.
- Deserializes the admin account data.
- Checks if the current admin has admin privileges.
- Deserializes the proposal data.
- Checks if the proposal is still active based on the current time.
- Sets the proposal as executed based on whether yes votes are greater than or equal to no votes.
- Serializes the proposal data.
