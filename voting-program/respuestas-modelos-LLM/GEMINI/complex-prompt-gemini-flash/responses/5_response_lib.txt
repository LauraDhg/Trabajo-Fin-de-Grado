Function "vault_program_id":
- Hardcoded program ID, which might need to be changed.
- If this ID changes the program will stop working.

Function "process_instruction":
- This is the main entry point, and uses a match statement to route instructions.
- The function unpacks the instruction data and calls the appropriate handler function.

Function "create_admin":
- Checks if the `admin_payer` is a signer.
- Checks if the `admin_account_dao` is already initialized.
- Derives a PDA for the admin account using `Pubkey::find_program_address`.
- Creates the admin account using `invoke_signed` with the derived PDA as a signer.
- Serializes the admin account data.

Function "update_admin":
- Checks that the `admin_account_dao` is owned by the program.
- Checks if the `admin_payer` is a signer.
- Checks that the `admin_payer` is the current admin.
- Updates the admin account with the new admin's pubkey.
- Serializes the updated admin account data.

Function "create_account":
- Checks if the `user_payer` is a signer.
- Checks if the `user_account_dao` is already initialized.
- Derives a PDA for the user account using `Pubkey::find_program_address`.
- Creates the user account using `invoke_signed` with the derived PDA as a signer.
- Serializes the user account data, initializing governance points to 10.

Function "open_proposal":
- Checks that the `user_account_dao` is owned by the program.
- Checks if the `user_payer` is a signer.
- Checks if the `proposal_account` is already initialized.
- Derives a PDA for the proposal account using `Pubkey::find_program_address`.
- Creates the proposal account using `invoke_signed` with the derived PDA as a signer.
- Serializes the proposal account data, setting a 1-hour voting window.

Function "vote_process":
- Checks that the `user_account_dao` and `proposal_account` are owned by the program.
- Checks if the `user_payer` is a signer.
- Checks if the `vote_record_account` is already initialized.
- Derives a PDA for the vote record account using `Pubkey::find_program_address`.
- Checks if the proposal is still open for voting.
- Updates the proposal's vote counts based on the user's vote and governance points.
- Creates the vote record account using `invoke_signed` with the derived PDA as a signer.
- Serializes the vote record, proposal, and user account data.

Function "manage_governance_points":
- Checks that the `admin_account_dao` and `user_account_dao` are owned by the program.
- Checks if the `admin_payer` is a signer.
- Checks that the `admin_payer` is the current admin.
- Adds or subtracts governance points from the user account.
- Serializes the updated user account data.

Function "execute_instruction":
- Checks that the `user_account_dao` is owned by the program.
- Checks if the `user_payer` is a signer.
- Performs different actions based on the `variant_instr`: creating, depositing, or withdrawing from a vault.
- Verifies that the `vault_program` and `ix_sysvar` accounts are correct.
- Checks the previous instruction to ensure it was a vault program confirmation.
- Calls the `send_create_vault_transaction` or `send_instr_to_vault_transaction` functions to execute a cross-program invocation (CPI) to the vault program.

Function "make_decision":
- Checks that the `admin_account_dao` and `proposal_account` are owned by the program.
- Checks if the `admin_payer` is a signer.
- Checks that the `admin_payer` is the current admin.
- Checks if the proposal is still active.
- Determines if the proposal passes or fails based on the vote counts.
- Updates the proposal's `executed` flag and serializes the updated proposal account data.

Function "send_create_vault_transaction":
- Creates and sends a transaction to a vault program to create a vault.
- Uses the `invoke_signed` function to sign the transaction with the vault's PDA.
- It sends an instruction with variant_instr, the admin ID, and the vault bump.
- The function includes the accounts the Vault Program expects.

Function "send_instr_to_vault_transaction":
- Creates and sends a transaction to a vault program to deposit or withdraw from a vault.
- Uses the `invoke_signed` function to sign the transaction with the vault's PDA.
- It sends an instruction with variant_instr, the amount, and the user ID.
- The function includes the accounts the Vault Program expects.
