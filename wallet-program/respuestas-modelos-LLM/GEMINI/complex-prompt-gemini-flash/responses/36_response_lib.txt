Function "process_instruction":
- Matches on instruction variants to call specific handler functions. This is standard practice.

Function "initialize_wallet_account":
- Checks if the provided system program account is indeed the system program.
- Uses `find_program_address` to derive the PDA. This is good for secure account derivation.
- Checks if the provided wallet account matches the derived PDA.
- Creates the account using `invoke_signed`, which is secure because it signs the instruction with the program's seed.
- Serializes the wallet data into the newly created account.
- No check to see if account is already initialized.

Function "deposit_amount":
- Checks if the wallet account owner is the program itself.
- Uses `find_program_address` and verifies that the provided wallet account matches the derived PDA.
- Deserializes the wallet data using `try_from_slice`.
- Uses `checked_add` for safe arithmetic.
- Serializes the updated wallet data.

Function "withdraw_amount":
- Checks if the wallet account owner is the program itself.
- Uses `find_program_address` and verifies that the provided wallet account matches the derived PDA.
- Deserializes the wallet data using `try_from_slice`.
- **VULNERABILITY**: Does not perform a checked subtraction. This can lead to underflows and potential vulnerabilities.
- Serializes the updated wallet data.

Function "transfer_amount":
- Checks if both source and destination wallet account owners are the program itself.
- Uses `find_program_address` and verifies that both provided wallet accounts match the derived PDAs.
- Deserializes the wallet data using `try_from_slice` for both wallets.
- Uses `checked_add` for the destination wallet, preventing overflows.
- **VULNERABILITY**: Does not perform a checked subtraction on the source wallet. This can lead to underflows and potential vulnerabilities.
- Serializes the updated wallet data for both wallets.
