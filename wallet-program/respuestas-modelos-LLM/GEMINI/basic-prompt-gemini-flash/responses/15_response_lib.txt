Function "process_instruction":
- Unpacks the instruction data into an `InstructionFormat` enum.
- Uses a `match` statement to call the appropriate function based on the unpacked instruction.
- Calls `initialize_wallet_account` for `CreateAccount` instructions.
- Calls `deposit_amount` for `IncreaseAmount` instructions.
- Calls `withdraw_amount` for `WithdrawAmount` instructions.
- Calls `transfer_amount` for `TransferAmount` instructions.

Function "initialize_wallet_account":
- Takes the program ID and an array of `AccountInfo` structs as input.
- Retrieves the user account, wallet account, and system program account from the `accounts` array.
- Checks if the user account is a signer.
- Derives the PDA (Program Derived Address) for the wallet account using `Pubkey::find_program_address`.
- Validates that the wallet account's key matches the derived PDA.
- Checks if the wallet account already has lamports.
- Creates a new `Wallet` struct with an initial amount of 0 and `initialized` set to true.
- Calculates the rent-exemption balance for the wallet account.
- Invokes the system program to create the wallet account using `invoke_signed`.
- Serializes the `Wallet` struct into the wallet account's data.
- Returns `Ok(())` if the operation is successful.
- Potential vulnerability: Integer overflow when calculating `wallet_len` or `wallet_rent` which could lead to account exhaustion
- Potential vulnerability: Incorrect account size. The program calculates the minimum rent-exempt balance based on the size of the `Wallet` struct after serialization. However, it doesn't ensure that the account created via `create_account` has the same size as the serialized `Wallet` struct. If the account size is smaller, the serialization will fail, and if it's larger, it could lead to wasted rent.

Function "deposit_amount":
- Takes the program ID, an array of `AccountInfo` structs, and an amount as input.
- Retrieves the user account and wallet account from the `accounts` array.
- Checks if the user account is a signer.
- Derives the PDA for the wallet account.
- Validates that the wallet account's key matches the derived PDA.
- Deserializes the wallet account's data into a `Wallet` struct.
- Checks if the wallet is initialized.
- Increases the wallet's amount by the specified amount.
- Serializes the updated `Wallet` struct back into the wallet account's data.
- Returns `Ok(())` if the operation is successful.

Function "withdraw_amount":
- Takes the program ID, an array of `AccountInfo` structs, and an amount as input.
- Retrieves the user account and wallet account from the `accounts` array.
- Checks if the user account is a signer.
- Derives the PDA for the wallet account.
- Validates that the wallet account's key matches the derived PDA.
- Deserializes the wallet account's data into a `Wallet` struct.
- Checks if the wallet is initialized.
- Checks if the wallet has sufficient funds to withdraw the specified amount.
- Subtracts the specified amount from the wallet's amount.
- Serializes the updated `Wallet` struct back into the wallet account's data.
- Returns `Ok(())` if the operation is successful.
- Potential vulnerability: Arithmetic error is handled using `checked_sub` but the custom error `MyError::ArithmeticError` is mapped to `ProgramError::Custom(1)` which might not be descriptive enough for debugging or client-side error handling. It would be better to define distinct custom errors.

Function "transfer_amount":
- Takes the program ID, an array of `AccountInfo` structs, and an amount as input.
- Retrieves the user account, source wallet account, destination user account, and destination wallet account from the `accounts` array.
- Checks if the user account is a signer.
- Derives the PDAs for both the source and destination wallet accounts.
- Validates that the wallet accounts' keys match the derived PDAs.
- Deserializes both wallet accounts' data into `Wallet` structs.
- Checks if both wallets are initialized.
- Adds amount to the destination wallet BEFORE substracting it from source wallet. In case the addition fails, the amount is not substracted from the source wallet, resulting in loss of funds.
- Checks if the source wallet has sufficient funds to transfer the specified amount.
- Subtracts the specified amount from the source wallet's amount and add it to the destination wallet's amount.
- Serializes the updated `Wallet` structs back into their respective wallet accounts' data.
- Returns `Ok(())` if the operation is successful.
- Potential vulnerability: The destination wallet's amount is increased before checking if the source wallet has sufficient funds. If the source wallet has insufficient funds, the function returns an error, but the destination wallet has already been credited, leading to a potential inflation of funds in the destination wallet. The destination wallet should be credited only if the funds are successfully debited from the source wallet.
- Potential vulnerability: The program transfers lamports from the source wallet to the destination wallet without invoking the system program. Therefore, only the `amount` field inside the wallet accounts gets updated. It does not update the actual SOL in the account.
